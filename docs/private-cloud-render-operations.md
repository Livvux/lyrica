# Private local Lambda/R2 exports

The branch extends the existing native/local editor with a single private owner, durable projects/media and cloud jobs. Existing native loopback authentication remains valid; browser access requires the private password. Old unbound localStorage data remains in place but must be re-uploaded into an owned project before export. A project switch remounts the editor and selects an owner/project-specific persistence key.

All Remotion packages and the deployed renderer use4.0.535. The pilot is Frankfurt, LyricsVideo,1280x720/24fps, maximum30seconds,2048MiB memory/disk,120second function timeout, reserved concurrency1, no retries. Cloud uses the Linux system sans-serif font; Local retains the existing quality profiles and desktop fonts. Long videos stay local. Ordinary continuous cloud usage is not yet authorized: this installation permits one additional cloud start for the remaining synthetic acceptance attempt, within the original totalUSD2. An unclear invocation consumes that attempt and retains the global reservation; it is never automatically resubmitted or silently replaced with Local.

Private R2 buckets are `lyrica-private-media` and `lyrica-private-renders`, EU Standard Storage, no public domain/r2.dev. Separate Object Read & Write tokens are bucket-scoped. The application chooses `media/<owner>/<project>/<filename>` and `exports/<owner>/<project>/<job>.mp4` after ownership checks. Only the output credential is included in the server-to-Lambda output-provider payload. Remotion's pinned provider does not support sessionToken; this is not a per-object temporary credential grant. Total retained application data and output reservations are bounded to512MiB.

The host config is `~/Library/Application Support/Lyrica/private/render-config.json`, mode0600 in a mode0700 directory. The owner personally enters the private password and S3 credentials using `scripts/setup-private-render.mjs` or the loopback-only web wizard. The web wizard expires after15minutes, performs same-origin/cookie checks, never logs secrets and refuses to overwrite an existing config. Do not put credentials in chat, argv, `.env.local`, a browser bundle or committed files. The protected production `.env.local` and `ecosystem.config.js` remain untouched.

AWS authentication uses the owner's existing `lyrica-pilot-operator` login session and assumes only `lyrica-remotion-client-pilot` for900seconds. No access keys are generated. The credential_process consumes AWS CLI credential export internally; its output must never be printed. If the session expires, the owner runs `aws login --profile lyrica-pilot-operator --region eu-central-1` personally. The application verifies the resulting account/role before reserving a Lambda attempt. Root/bootstrap profiles are not used for rendering.

Cloud starts persist before invocation. Closing a tab ends observation only. Cancel writes Remotion's cancellation signal and stays pending until remote progress confirms it. Refresh/restart observes the stored job; unknown starts require operator reconciliation. Terminal jobs clean only `jobs/<job>/` and `renders/<renderId>/`. Failed deletion keeps quota reserved and retries later. A successful R2 output remains downloadable if internal S3 cleanup is pending. Download GET redirects to an authorized five-minute R2 URL with no-store/no-referrer; its storage key and credentials never come from the client. Local bundle assets are served only on127.0.0.1 with a random secret route, range support and symlink/path checks.

Do not spend another attempt to recover an uncertain result. The pilot code lifecycle currently expires all objects after1day; a persistent renderer-code prefix needs a separately reviewed/approved CloudFormation lifecycle change. Do not silently change it.

The actual existing PM2 `lyrica` entry was stopped, cwd`/Users/livvux/dev/lyrica`, port3002; no Lyrica listener was present. Re-check that state before switching. Production is a synced non-Git directory and uses protected host config. Use only the repository's reviewed `deploy.sh` (rsync exclusions preserve `.env.local`, `ecosystem.config.js` and host-specific files); do not run until the PR/review and local switch are ready. First save a private source snapshot excluding secrets, node_modules, build output and temp files. Never stop unrelated processes.

Rollback restores that source snapshot with the same exclusions, rebuilds and restores the exact prior PM2 state. Setting cloudEnabled=false blocks new cloud starts, while existing job status/cancel/download remain accessible through ownership checks. Preserve the private SQLite database and R2 objects during rollback; deleting them could lose job identity or ownership. Original `/Users/livvux/lyrica` and the native/T3 branch remain unchanged.
